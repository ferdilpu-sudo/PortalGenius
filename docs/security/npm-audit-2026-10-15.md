## Original finding
An operator reported `npm ci` finding **4 high severity vulnerabilities**. GitHub Actions audit reproduced the report in the development toolchain:
- `wrangler` (direct dev dependency),
- `miniflare` (transitive),
- `sharp` (transitive; advisory GHSA-wq5f-xc86-pv6w),
- `undici` (transitive; multiple advisory entries).

Source diagnostic run: https://github.com/ferdilpu-sudo/PortalGenius/actions/runs/38705788264

## Remediation
Pinned `wrangler` to exact `4.151.0` and regenerated the lockfile using the npm resolver. **No `--force` used**. Audit of the candidate in GitHub Actions yielded 0 across info/low/moderate/high/critical.

Evidence: https://github.com/ferdilpu-sudo/PortalGenius/actions/runs/38706529542 and https://github.com/ferdilpu-sudo/PortalGenius/actions/runs/38706715872

CI now runs `npm ci` plus `npm audit --audit-level=high`, typecheck, unit tests, Windows bootstrap parser and Vite build. Treat newly discovered advisories as independent follow-up findings, not proof of permanent safety.

The Windows npm message concerning approval of `esbuild` / `workerd` install scripts should be reviewed separately, and does not justify automatically allowing all scripts or running `npm audit fix --force`.
